# Stage 3 · 模型选型

## 目标

为每个子问选定模型，并且**能说清楚为什么不是别的**。

选型的产出不是"我们采用 X 模型"，而是一张候选比较表 + 淘汰理由 + 适配性论证。

## 时长

2–4 小时

## 输入

- 子问任务卡（Stage 2）
- `task_type`
- 数据资产清单
- `references/model_fit_rubric.md`
- 可选：外部数模字典（5713 条，见下方"用字典生成候选"）

## 执行步骤

### 步骤 1 · 生成候选

每个子问至少 2–3 个候选，且**不能同族**。

**用字典生成候选**（推荐）：若有外部数模字典，先按大类或场景检索，避免凭印象选型。

```bash
# 按题型浏览该大类的全部候选
python <wf>/scripts/query_model_dict.py --category 优化模型 --limit 15 --brief

# 按题目场景关键词检索（如"小样本 贫信息""空间散点"）
python <wf>/scripts/query_model_dict.py --scene <场景关键词> --limit 10
```

字典按大类分布为：预测分类 2250 / 评价 1183 / 优化模型 1087 / 数据预处理 674 / 其他 519。
查询方式与许可约束见 `model_fit_rubric.md` 的「外部数模字典查询」一节——
**字典内容不得复制进论文**，论文中引用模型原理应引用教材或学术文献。

同族候选是典型问题：候选 1 是 BP，候选 2 是 RBF，候选 3 是 LSTM——看着有三个选择，实际是同一个选择做了三次。真正的权衡应发生在结构、假设或求解机制不同的候选之间：

| 候选类型 | 例 |
|---|---|
| 统计/机理 vs 机器学习 | 回归 vs 集成树 |
| 确定性 vs 随机性 | 优化模型 vs 仿真 |
| 参数 vs 非参数 | 参数回归 vs 样条/GAM |
| 精确 vs 启发式 | 分支定界 vs 元启发式 |

若最终仍选同族模型，必须解释差异与筛选依据。

### 步骤 2 · 适配性判定

对每个候选，按 `references/model_fit_rubric.md` 出具四选一结论：

| 结论 | 含义 |
|---|---|
| **合适** | 与题目目标、数据结构、变量类型基本匹配 |
| **有条件合适** | 方向正确，但需满足额外条件或补充处理 |
| **不合适** | 与任务目标、数据类型或核心假设明显冲突 |
| **证据不足** | 现有信息不足以可靠判断 |

判定需覆盖六个方面：适用场景、数据要求、关键假设、输入输出、禁忌点、检验方法。

**"证据不足"是合法结论。** 数据还没看清时强行选型，比标注证据不足再去补数据要糟。

### 步骤 3 · 选型论证

对每个子问写一段论证，必须包含：

```
问题X要求【问题目标】。根据题目条件和数据特征，该问题在数学上属于【问题类型】。
考虑到【模型适用理由】，选择【模型名称】进行求解，并针对【本题特点】
对模型的【目标函数、约束或参数】进行调整。
```

**针对性判定（硬性检查）**：把段落中的赛题背景删掉，如果这段话仍然能原封不动地用于其他题目，说明写的是模型教科书介绍，不是针对本题的选型。

### 步骤 4 · 反事实与淘汰理由

对每个被淘汰的候选，写明：

- 它在哪个具体环节不满足（数据规模？变量类型？约束形式？求解时间？）
- 如果坚持用它，需要付出什么代价

**淘汰理由的质量决定选型的可信度。** 只写"本模型应用广泛，故选用"等于没论证。

### 步骤 5 · 可行性验证

在完整实现前做最小可运行验证，记录：

- 问题规模与求解器状态
- 耗时与内存
- 失败条件（什么情况下跑不出来）

代码行数不作为标准，能跑通并有合理输出才是。

### 步骤 6 · 模型族一致性

检查全文模型族是否自洽。例如 Q1 用确定性优化、Q3 突然用蒙特卡罗，需要显式说明触发条件。

若后续 Stage 5 发生切换，必须在 `stages.5` 记录原因，并回检 Stage 3 的论证。

## AI 使用提示

AI 可用于候选推荐、方案比较、适用条件分析、局限性讨论。但必须说明：

- 最终模型如何确定
- 哪些建议被舍弃
- **核心模型是否由参赛队自己推导**

AI 推荐的模型直接照搬，是"模型名称与实际实现脱节"的主要来源。

## 产物

`decision_log.json` 的 `stages.3`：

```
candidate_models      候选表（含适配性四分类结论）
selected_per_subproblem  每问选定模型
rejection_log         淘汰理由
toy_demos_passed      可行性验证结果
red_team              反事实攻击记录
model_family_consistency  模型族一致性说明
```

## 5 维评分

| 维度 | 判据 |
|---|---|
| `1_candidate_diversity` | 候选是否跨族，有无真实权衡 |
| `2_selection_rationale` | 论证是否针对本题（删背景后是否通用） |
| `3_data_fit` | 模型数据要求与现有数据是否匹配 |
| `4_solver_feasibility` | 是否做过可行性验证，有无失败条件 |
| `5_literature_support` | 是否有可核验的依据（文献/经典方法/数据特征） |

## 检查清单

- [ ] 每个子问 ≥2 个候选，且不同族
- [ ] 每个候选有适配性四分类结论
- [ ] 适配性判定覆盖了六个方面
- [ ] 选型论证通过"删背景"检验
- [ ] 每个淘汰候选都有具体的不满足环节
- [ ] 做过最小可运行验证
- [ ] 全文模型族自洽，切换有说明
- [ ] 说明了哪些 AI 建议被舍弃、核心模型由谁推导

## 常见失败

| 失败 | 表现 |
|---|---|
| 堆砌复杂度 | 简单模型已能达标，仍上神经网络/多模型组合，说不出必要性 |
| 名称脱节 | 说用了 AHP，实际只是拍了个权重表 |
| 模型与问题不匹配 | 题目要分类却用回归，要时序却用截面 |
| 无可行性验证 | 选了个 NP-hard，最后跑不出来临时换模型 |

## 退出条件

- `verdict = pass`，或
- `verdict = carryover`
