# Stage 8 · 论文装配

## 目标

把前面七个阶段的产出装配成一篇符合当届规范、内部自洽、可提交的论文。

本阶段同时负责 **AI 使用披露**——这是 2026 年规则的明确要求，不是可选项。

## 时长

12–30 小时（全文写作的绝大部分）

## 输入

- Stage 1–7 的全部产物
- `references/writing_spec.md`（章节规范与篇幅分配）
- `references/ai_usage_governance.md`
- `decision_log.compliance.ai_usage` 台账

## 论文章节体系

| 顺序 | 章节 | 要点 |
|---|---|---|
| — | 承诺书 | 第一页，按当届模板 |
| — | 编号专用页 | 第二页 |
| — | 摘要专用页 | 第三页，含标题与关键词，**不超一页**，从此页开始编页码 |
| 1 | 问题重述 | 背景、问题回顾，可含研究综述 |
| 2 | 问题分析 | 各问分析、求解框架图、子问关系 |
| 3 | 模型假设 | 每条含依据与影响 |
| 4 | 符号说明 | 三线表：符号 / 含义 / 单位 |
| 5 | 数据与预处理 | 仅多问共用数据时集中设置 |
| 6+ | 各子问模型建立与求解 | 每问独立成一级章 |
| n | 模型评价与推广 | Stage 7 产出 |
| n+1 | 参考文献 | 与正文引用一一对应 |
| n+2 | 附录（页数不限） | 代码、补充推导 |
| — | 支撑材料 | AI 使用详情（如使用 AI） |

**国赛不要目录**，正文尽量控制在 30 页以内，附录不限但需与正文一起装订。

## 摘要规范

| 项 | 要求 |
|---|---|
| 篇幅 | A4 一页以内，约 800–1000 字 |
| 结构 | 引言段（背景 + 核心问题）→ 每问一段 → 总结段（创新、优势、局限、改进） |
| 人称 | 第三人称，用"本文""该模型"，不用"我""我们" |
| 禁用 | 图、表、公式、参考文献编号、未经解释的缩写 |
| 禁用 | "结果良好""效果显著"等无量化依据的空话 |
| 关键词 | 4–6 个，从实际问题、主要模型、求解算法三个方向选 |

**不要预设各问层层递进。** 先判断真实关系，再选择承接方式；无明显联系时不强行写承接语。尤其不要把第三问固定写成"不确定性分析"或"改进模型"。

**摘要必须在全文完成后撰写**，且所有数值回指正文。

### 摘要自查清单（AutoClaw 增强）

> 增强来源：AutoClaw `cumcm-workflow-9` 阶段 6「摘要与首页」——全文完成后，逐条过稿。

**独立阅读性第一关**：让非本领域研究者仅凭摘要说得出"解决什么问题 / 用什么模型 / 得到什么结果"，三要素缺一即严重警告；若说不全，回写摘要。

**虎头·猪肚·豹尾结构**：
- 虎头（两句话 3-4 行）：一句背景 + 一句引出核心问题；不写预处理细节、不罗列模型体系。
- 猪肚：一问一段；每段按真实内容写：任务→数据处理→模型名称及数学类型→建模思想→算法→关键量化结果→检验结论。承接语按**真实关系**选择，禁止预设层层递进。
- 豹尾：真实创新点 + 检验表现 + 推广方向 + 局限与改进；**正文没有的检验不得虚构**。

**15 项自查清单**：

- [ ] 篇幅一页内，800-1000 字
- [ ] 题目准确、具体、简洁，与正文一致；主模型或最具创新性模型进标题，禁谐音梗/方法堆砌
- [ ] 第三人称
- [ ] 无图表、公式、引用编号、未经解释的缩写
- [ ] 每问一段，段首有该问任务
- [ ] 每个模型写出了数学类型（如 0-1 整数规划 / 多目标优化 / 综合评价）
- [ ] 软件不替代算法（"采用遗传算法搜索最优解，并通过 MATLAB 完成计算" ✅；"使用 MATLAB 求解，结果良好" ❌）
- [ ] 量化结果优先（数值/排序/预测值/最优方案/准确率/误差/收益）
- [ ] 承接语与真实关系一致，无强行递进
- [ ] 创新点是真实内容，非套话
- [ ] 检验结论来自正文（不得虚构）
- [ ] 局限性有描述
- [ ] 关键词 4-6 个，从问题词/模型词/算法创新词三方向选，禁宽泛词与软件名
- [ ] 每个模型、数值、检验至少回指一处正文证据
- [ ] 与正文零冲突校验通过

**规则核对三重门 · 第 2 道**：复核当届摘要页与格式规范（页码从摘要页起、页脚居中、摘要页无身份信息等），更新 `compliance.ruleset.verified_at`。

## AI 提示词使用规范

**完整提示词见 `references/prompt_library.md`** —— 含 11 个板块、14108 字，
逐字提取自 BZD 数模社《2026 年数学建模竞赛模板》：

| 板块 | 适用阶段 |
|---|---|
| 摘要 | Stage 8（**必须在全文完成后**调用） |
| 第一章 · 问题重述 | Stage 8 |
| 第二章 · 问题分析 | Stage 2 / Stage 8 |
| 第三章 · 模型假设 | Stage 4 |
| 第四章 · 符号说明 | Stage 4 |
| 第五章 · 模型建立与求解 | Stage 5 |
| 第六章 · 模型评价与推广 | Stage 7 |
| AI 工具使用声明 | Stage 8 |
| 参考文献与附录 | Stage 8 |
| AI 工具使用详情（通用版 / 直接生成版） | Stage 8 支撑材料 |

标准范式包含四段：

```
【角色】你是一名熟悉全国大学生数学建模竞赛评审标准的学术写作专家。
【任务】1. …  2. …  3. …
【结构】第一段…主体部分…最后一段…
【语言与事实要求】使用第三人称…所有模型、算法、数值、检验和结论必须来自
                  论文正文；信息不足时标记"正文未明确说明"，不得自行编造。
```

**第四段（事实约束）不可省略。** 没有事实约束的提示词会让 AI 生成读起来通顺但论文中不存在的内容——这类错误在终审时极难发现。

各章节的提示词应在**该章节依赖的内容已完成**后使用，不能让 AI 凭空生成。
摘要提示词尤其如此：它要求把完整正文粘贴给 AI，必须在全文写完后调用。

## 章节写作细节（AutoClaw 增强）

> 增强来源：AutoClaw `cumcm-workflow-9` 阶段 5「章节写作」。对应章节写作时应用，
> 与 `references/writing_spec.md` 互为操作细则。

**总纪律**：只写思路不写结果（分析章）；模型修改后回写清理旧符号、旧变量、旧单位；AI 提示词仅作草稿加速，一切文献、数据、检验结果禁止虚构，信息不足标"待核对"。

### 第一章 · 问题重述细节

- **1.1 研究背景**（1-3 段）：对象定义→现实背景→主要矛盾→一句引出核心问题；四要素齐全，删除与任务无关的展开。
- **1.2 问题回顾**：按(1)-(n)逐问改写；用任务动词（分析/识别/预测/评价/比较/设计）；保留时间、单位、样本规模、约束与输出形式。
- **1.3 研究综述**（约 500 字，3-4 段，四段式：总体现状→方法方向一→方法方向二→不足与本文切入点）。**永不虚构作者/题名/期刊/年份**；文献四验（作者/题名/刊物/年份卷期页码）；无核验文献时写方法级综述并标注"具体文献需要补充并核验"。
- 改写五法：信息提取→内容分类→逻辑重组→语言压缩→条件核对。常见错误：复制原题（查重风险）、同义词替换式改写、背景喧宾夺主、写成问题分析、漏条件、堆原题图表。

### 第三章 · 模型假设细节

- **4-8 条**；三类来源（题目明确给出 / 由题意合理推出 / 模型必需）；单条结构 = 内容 + 依据 + 建模作用。
- 十类常见假设对号入座：数据有效性 / 小概率排除 / 主次因素 / 平稳性 / 理想化 / 分布形式 / 变量关系 / 行为决策 / 时空口径 / 独立性。
- **八条禁忌**：不假设模型或指标体系必然正确；不忽略题目要求研究的核心因素；不把"插值补全"等预处理写成假设；不用近义句重复"数据可靠"；不写入后文完全未用的假设；过强假设（完全理性/完全独立/永久稳定）无依据不写；检验与假设矛盾必须回改；不写空泛开头（"为使模型更加完备"）。
- 逐条登记"假设 → 后文对应位置"（变量/公式/约束/检验/局限），写入 `stages.8` 供回检。

### 第四章 · 符号说明细节

- 三线表三列：**符号 / 含义 / 单位**；表题在上；符号列居中、含义列左对齐。
- **收 6 类**：核心变量参数 / 多问共用 n,m,t,w / 关键系数 / 全局下标 / 向量矩阵目标函数 / 自定义指标。
- **不收 5 类**：一次性临时变量 / 局部符号 / 常见运算符 / 已废弃符号 / 程序内部变量。
- **一致性 5 条**：一符一义；一变量一符；区分大小写粗体标量向量矩阵；下标指代固定；防 p 同时表示概率/权重/价格。符号表**不替代**正文首次定义。
- 单位：有量纲必标；无量纲全文统一选 `-`、`/`、`无量纲` 之一；与正文口径一致（元≠万元）。

### 第五章 · 代码转正文（AutoClaw 增强）

把求解代码转化为连续段落"模型建立与求解过程"：
- 按实际求解顺序组织（数据输入→处理→指标计算→建模→参数设置→求解→输出）
- 核心计算用"文字 + LaTeX 公式"表达并释义；**函数名/类名/程序变量名全部替换**为实际意义中文名或规范数学符号
- 循环判断概括数学逻辑不写语法；可视化/环境/路径/库导入/输出语句不写入；参数无依据不虚构

## AI 使用披露

### 声明模板

**未使用 AI 工具：**

> 本参赛队在竞赛过程中未使用任何 AI 工具。

**使用了 AI 工具：**

> 本参赛队在竞赛过程中使用了 AI 工具，主要用于【文献检索辅助、建模思路讨论、数据处理建议、程序代码调试、结果核验、图表优化、语言润色和格式检查等实际用途】，详细使用情况见支撑材料《AI工具使用详情.pdf》。

### 详情材料要求

每类用途需写明三列：

| AI 可提供什么 | 主要用途 | **必须人工核验的内容** |
|---|---|---|

第三条是关键。只写"用了 AI 调试代码"不构成披露，必须写清楚**参赛队如何验证 AI 的产出**。

示例：

| AI 可提供 | 主要用途 | 必须人工核验 |
|---|---|---|
| 语法错误排查、报错分析、维度检查 | Python / MATLAB 程序报错分析与局部调试 | 说明报错信息、AI 修改建议、实际采纳内容和重新运行结果 |
| 残差分析建议、拟合优度检验、交叉验证方案 | 误差分析、残差检验、模型对比方案讨论 | 说明检验数据、指标、计算过程和结果，**不得让 AI 直接生成检验数值** |
| 缺失值处理方法比较、标准化方案比较 | 缺失值与异常值处理方法比较、特征筛选 | 说明最终采用的方法、参数和处理前后变化，**不得让 AI 虚构、补造或任意修改数据** |

### 生成方式

```bash
python <wf>/scripts/render_ai_usage.py \
  --decision-log <cwd>/state/decision_log.json \
  --paper-workspace <cwd>/paper_workspace \
  --support-dir <cwd>/support_materials
```

`ai_usage` 为 `null` 时脚本报错——**必须显式确认为"未使用"或列出记录**，缺失不能被解释为未使用。

## 格式要求

| 项 | 要求 |
|---|---|
| 页边距 | 上下左右各 ≥ 2.5 cm |
| 页码 | 从摘要页开始，页脚中部，阿拉伯数字从 1 连续编号 |
| 匿名 | 摘要页、正文、附录任何位置不得出现身份、学校、赛区信息 |
| 引用 | 正文引用处标注，参考文献列表与正文一一对应 |
| 装订 | 从左侧装订 |

字号、字体、行距、颜色**国赛不做统一要求**，但全文必须一致。

## 5 维评分

| 维度 | 判据 |
|---|---|
| `1_structure_completeness` | 章节是否齐全、编号是否连续 |
| `2_cross_stage_consistency` | 摘要/正文/图表/结果是否自洽 |
| `3_format_compliance` | 页边距、页码、匿名、篇幅是否符合当届要求 |
| `4_ai_disclosure` | 声明与详情是否完整、是否写明人工核验 |
| `5_abstract_quality` | 摘要结构、人称、量化结果、禁用项 |
