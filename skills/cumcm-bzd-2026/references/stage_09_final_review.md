# Stage 9 · 终审与提交

## 目标

在提交前完成三件事：**合规门通过、质量评审完成、问题闭环**。

本阶段是唯一会触发"回退重改"的阶段。

## 时长

2–6 小时

## 输入

- 完整论文与支撑材料（Stage 8）
- 完整赛题
- `references/rules_baseline.md`
- `references/anti_patterns.md`
- 可选：组别、赛区、学校全称（用于竞争环境修正）

## 步骤 1 · 合规门（先做，不通过不继续）

逐项检查，任一失败即触发回退：

| 检查项 | 判定 |
|---|---|
| 页数 | 正文 ≤ 30 页（附录不限但须装订） |
| 匿名 | 摘要页、正文、附录无任何身份/学校/赛区信息 |
| 摘要 | 不超一页，从此页开始编页码 |
| 目录 | 国赛不得出现目录 |
| 页边距 | 四边 ≥ 2.5 cm |
| 参考文献 | 正文引用处标注，列表与正文一一对应 |
| AI 披露 | 已使用则提供详情材料；未使用则提供声明 |
| 占位符 | 无 XXXX、待填、示例值等残留 |
| 装订材料 | 附录与正文一起装订 |

**规则以当届官方通知为准。** 仓库基线不能替代当届通知——这是本阶段第 3 次核对（Stage 1、8、9 各一次）。（规则核对三重门 · 第 3 道）

### 合规细项增强（AutoClaw）

**匿名性逐项扫描**（不只扫正文）：摘要、正文、附录、页眉页脚、文档属性、代码注释、路径、截图、文件名都要过。

**附录与复现终检 10 项**：

- [ ] 输入文件存在且字段与正文一致
- [ ] 无绝对路径
- [ ] 关键参数与正文一致
- [ ] 目标函数与约束与正文一致
- [ ] 随机算法固定种子或说明可重复运行
- [ ] 无缺失自定义函数与依赖
- [ ] 程序能产出正文主要数值与图表
- [ ] 代码有注释，无无关测试
- [ ] 无账号密码密钥
- [ ] 支撑材料代码与附录展示一致

无程序时附录明确写"本论文没有用到程序"。

## 步骤 2 · 质量评审

评审分三个层次，前者不受后者影响：

### 层次零：rubric 冻结 + 90% 封顶（AutoClaw 增强）

> 增强来源：AutoClaw `cumcm-workflow-9` 阶段 8「全面审查 II：综合评审」——保证"陌生评委视角"，
> 且评审结论不被 AI 和历史对话锚定。

1. **隔离声明**：本评审只依据"当届赛题 + 当前论文"，不使用历史对话中的解题思路、模型偏好或既有结论。
2. **先读题分解任务，再制定并冻结本题专用百分制 rubric**（写入 `stages.9.rubric_frozen_at` 带时间戳），**然后才读论文**——防止先入为主。
3. rubric 参考配比：摘要 10 分、格式 10 分、模型假设+建立+求解合计 70-75 分、其余相关质量 5-10 分；逐维配"满分行为描述"。
4. **90% 封顶**：每个数值维度得分 ≤ 该维权重 × 0.9（满分论文理论上限 90/100）；封顶扣除标注"评委满分保留"，不算论文缺陷，释放的 10% 不加回别处。
5. 每个给分/扣分点必须带位置证据（页码 / 公式号 / 图表号）。
6. **红队攻击**（championship 模式）：以反方评委攻击最弱章节，产出问题并入回修协议。

### 层次一：论文质量得分

只评价论文本身，不涉及竞争环境：

| 维度 | 关注 |
|---|---|
| 任务完成度 | 各问是否都回答了，输出形式是否符合要求 |
| 模型合理性 | 模型与问题是否匹配，选型是否有论证 |
| 求解质量 | 是否有最优性证据、是否可复现 |
| 结果可信度 | 数值是否真实、是否经过检验 |
| 验证情况 | 检验、稳健性、一致性是否充分 |
| 摘要与格式 | 结构、人称、量化结果、排版 |

### 层次二：省奖竞争修正

在质量得分基础上，结合**参赛组别**与**所在赛区的省奖竞争强度**修正。修正范围最高 ±10 分。

### 层次三：国奖竞争修正

进一步结合**赛区国奖难度、学校历史国奖表现、是否数模强校、指导教师集中度**修正。修正范围最高 ±15 分。

**学校、赛区和指导教师不改变论文质量得分**，只影响竞赛环境下的奖项判断。

### 创新盲区提示

每年都有少量论文因解题路径高度新颖、超出常规评阅预期而获奖。AI 评审难以可靠识别这类突破性价值，可能**低估**真正原创的非常规方案。若自评得分偏低但方案确实有独到之处，不必因分数推翻方案。

## 步骤 3 · 反模式扫描

按 `references/anti_patterns.md` 逐条扫描，重点命中项：

| 类别 | 高频问题 |
|---|---|
| 摘要 | 无定量结果、与正文不符、含图表公式引用 |
| 假设符号 | 假设无依据、符号重复定义、无单位 |
| 模型选型 | 名称与实现脱节、候选同族、无可行性验证 |
| 求解 | 无随机种子、无 sanity check、数量级离谱 |
| 结果 | 只报数字、无基线对比、图表不可读 |
| 稳健性 | 仅 OAT、无稳健区间、扰动幅度失真 |
| 子问协调 | 各做各的、模型族冲突、**跨问口径漂移** |
| 评价 | 套话批判、优点夸大、推广空泛 |
| 呈现 | 公式无编号、图号错乱、引用不规范、缩写无全称 |

**跨问口径漂移是硬伤级问题**：下游复用上游配置或结果时，数值悄悄改变且正文无解释，评委按题号一对照即可发现。

## 步骤 4 · 问题闭环

发现问题后按归属回退，**不暂停交付给用户**：

| 问题归属 | 回退到 |
|---|---|
| 模型与问题不匹配 | Stage 3 |
| 求解错误、结果不可信 | Stage 5（按 Qi 局部重跑） |
| 检验不足 | Stage 6 |
| 写作、格式、披露 | Stage 8 |
| 渲染器问题 | 修复脚本 |

改完重进 Stage 9，**只重跑受影响的检查**，直到 `submission_ready=true` 且无致命违规。

每次回退写入 `stages.9.redo_log`，含：问题、归属、回退目标、修改内容、复检结果。

## 26 项 AI 合规清单（AutoClaw 增强 · 2026 六维度）

> 增强来源：AutoClaw `cumcm-workflow-9`（阶段 7/9）。每条标注 `合格 / 存在问题 / 待核实`，附位置与修复建议；
> 逐项无空项。**死亡项**（AI 主导核心建模 / 虚构数据或文献 / 声明与实际矛盾）命中即 `P0 → block`。

**A. AI 新规合规（4 项）**
- [ ] A1 声明已按 2026 规范生成，位置在模型评价之后、参考文献之前，句式符合当届要求
- [ ] A2 支撑材料《AI工具使用详情.pdf》四要素齐全：工具名称版本型号 / 具体用途环节 / 主要提示方式与过程 / 采纳内容+人工修改核验
- [ ] A3 AI 使用台账逐条记录（工具/版本/日期/环节/用途/关键提示与输出/采纳/人工核验），`null` 不得视为未使用
- [ ] A4 AI 工具未列入参考文献；AI 发现的文献核验后引原始文献

**B. AI 幻觉与数据真实性（4 项）**
- [ ] B1 无虚构数据、结果、检验——数值均来自真实程序输出
- [ ] B2 无虚构文献（作者/题名/刊物/年份卷期页码四验）
- [ ] B3 数据来源与预处理如实标注，AI 未补造或任意修改数据
- [ ] B4 摘要与正文中每个数值、检验至少回指一处证据

**C. 建模逻辑与题意适配（5 项）**
- [ ] C1 每问目标任务均已覆盖，无漏问漏条件
- [ ] C2 模型选择有针对性论证（非"时髦模型名"、非"使用遗传算法"式空话）
- [ ] C3 假设/约束与题意一致，无未经说明的擅自增删
- [ ] C4 跨问联动真实（非"写文字说基于问题一"的假联动）
- [ ] C5 建模口径全文统一（符号/单位/指标体系/目标函数）

**D. 求解及结果合理性（3 项）**
- [ ] D1 求解可复现（代码/随机种子/参数设置），最优性或结果有证据
- [ ] D2 结果通过合理性审查（物理/数值边界、数量级、约束满足），异常已归因
- [ ] D3 检验指标量化并匹配模型类型；训练集拟合效果不算验证

**E. 官方写作规范（6 项）**
- [ ] E1 篇幅符合当届规范（正文 ≤30 页等）
- [ ] E2 匿名性通过（摘要/正文/附录/页眉页脚/文档属性/代码/文件名）
- [ ] E3 章节结构完整、编号连续；国赛不设目录
- [ ] E4 摘要符合规范（一页内、第三人称、量化结果、无图表公式引用）
- [ ] E5 参考文献 GB/T 7714 体系内格式统一，与正文引用一一对应
- [ ] E6 图表引用与题注编号连续、格式统一

**F. 排版与页数（4 项）**
- [ ] F1 页边距/页码/字体/行距全文一致
- [ ] F2 无占位符（XXXX、待填、示例值）与截图残留
- [ ] F3 页数符合当届上限，附表/附图清单完整
- [ ] F4 附录与支撑材料完整（程序可复现、含文件清单、命名与大小合规）

## 步骤 5 · 提交包

```
<submission>/
├── 论文正文.pdf          含承诺书、编号页、摘要页、正文、附录
├── 支撑材料/
│   └── AI工具使用详情.pdf （仅在使用 AI 时）
└── 程序与数据（如赛区要求）
```

最终核对：文件完整性、命名符合赛区要求、格式（PDF）、大小限制。

## 5 维评分

| 维度 | 判据 |
|---|---|
| `1_compliance_gate` | 合规门是否全部通过 |
| `2_quality_score` | 论文质量得分与扣分明细 |
| `3_issue_closure` | 发现的问题是否全部闭环（非"已知悉"） |
| `4_consistency_final` | 跨章节一致性终检 |
| `5_submission_integrity` | 提交包是否完整、命名与格式是否符合要求 |

## 退出条件

- 合规门全部通过 且 无 high-severity 未闭环问题 → `submission_ready = true`
- 否则继续回退闭环，直至满足

## 最后提醒

本工作流的所有评分、位次预测和备赛建议均为**经验估计**，不代表官方评审结果、实际排名或奖项承诺。最终以当届组委会及赛区发布的正式规则为准。
