# Stage 2 · 赛题解析与任务拆解

## 目标

把题面从"一段自然语言"变成"一组可执行的任务卡"，并识别出题面**没有明说**但会影响求解的条件。

这一阶段的输出决定了后面所有工作的边界。题目理解错一层，后面全错。

## 时长

2–3 小时

## 输入

- 完整赛题与附件
- `decision_log.json` 的 `task_type` 与 `problem_scan`

## 执行步骤

### 步骤 1 · 逐句释义

对题面逐句处理，不放过任何一句。每句输出三列：

| 原文 | 释义 | 隐含要求 |
|---|---|---|

重点关注这几类措辞，它们通常对应隐藏条件：

- **"合理"**：需要给出判定标准，不能拍脑袋
- **"尽可能" / "最优"**：需要明确目标函数
- **"考虑…影响"**：要求做敏感性或对照分析
- **"给出…方案"**：要求可执行的输出，不是原则性描述
- **"分析…关系"**：要求量化关系，不是定性描述
- **时间、范围、精度限定词**：直接构成约束

**AI 使用提示**：AI 可用于条件梳理与遗漏提醒，但**必须逐条对照原题核对**。AI 对题意的误解是高频错误来源，误读往往很隐蔽——它生成的内容读起来是通顺的。

### 步骤 1b · 逐句翻译台账（AutoClaw 增强）

> 增强来源：AutoClaw `cumcm-workflow-9` 阶段 1「题面翻译」——把上表的"释义"升级为可审计台账，
> 用于题目复杂、子问多或往年常因漏读丢分的赛题。简单题可只做编号+覆盖台账。

翻译 = 从竞赛散文到建模语义的**语义翻译**，不是语言转换。默认每句话都携带定义、机制、约束、数据线索、评价目标、交付物或依赖。

**1. 定位锚点与编号单元**：从题目标题起读；标题前竞赛名、年份、格式提醒、页眉水印、提交须知一律排除且只作审计注记。整题通读一遍重建全局故事后，**一句完整原句一个单元**（分号/枚举仅在各自含独立可执行要求时才拆分），编号 `B01 / Q2-04 / A01` 全文稳定不变。

**2. 十类角色标注**（一句可多标）：

| 角色 | 含义 |
|---|---|
| context | 背景 |
| entity | 对象 |
| definition | 定义 |
| mechanism | 机制 |
| given | 已知 |
| constraint | 约束 |
| task | 任务 |
| objective | 目标 |
| validation | 检验要求 |
| deliverable | 交付物 |

凡改变解法的角色必须记录。

**3. 覆盖台账**（核心表，逐单元一行，保证"每句实质内容恰好入账一次"）：

| 编号 | 题干原句(原文,禁省略号) | 通俗而精确的翻译 | 明示条件/数据 | 隐含建模信号 | 与前后内容的联动 | 漏读后果 | 后文必须出现的证据 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

**4. 翻译六问**：关于什么实体或量？已知/未知/可控/观测/潜在？断言了什么关系、边界或动作？在什么总体、空间、时间、条件与单位上？对后面哪问重要？后文模型/算法/结果/检验必须展示什么？

**5. 量词保真**：`不考虑/仅/至多/至少/必须/不得/尽量` 的强度原样保留；嵌套量词（每对象/每期/每轮）逐层保留；每个数字绑定实体与单位。

**6. 最易漏读句 5-12 条**：写出诱误读法与正确解读。优先覆盖：数值限制、否定词、比较基线、数据来源限制、重复测量结构、几何条件、时间范围、输出格式。

**7. 术语与口径表**：每个定义或可能歧义术语 → 原文定义、采用解释、单位/范围、影响的问题；**区分题面事实与模型假设**。

**8. 逐问输入-任务-输出表**：`问题 | 直接输入 | 任务 | 约束 | 输出 | 依赖前问 | 被后问复用`。

**9. 歧义处理**：引用原句 → 列出合理解释 → 指出结果如何随解释变化 → 仅当语境明确支持时才选定；否则建议情景化/灵敏度处理。**不得虚构"官方解读"。**

**10. 完整性核验（退出前必做）**：实质单元数 = 台账行数；每个编号问题都在阶段 3 的联动链中；附件说明无遗漏；歧义未决项列出；OCR 不确定处标记待人工目验。

写入 `stages.2.translation_ledger`，供 Stage 3 联动链与 Stage 5 求解直接引用。

### 步骤 2 · 识别隐藏条件

常见的三类：

1. **数据隐含**：附件字段口径不一致、单位混用、存在重复测量或删失
2. **物理/业务隐含**：变量取值范围、守恒关系、时序先后约束
3. **评价隐含**：题目没说"用什么指标评价"，但从问题性质可以推出

每条隐藏条件要写明：从哪句话/哪个数据特征推出、若不处理会怎样。

### 步骤 3 · 子问任务卡

每个子问一张卡，字段固定：

| 字段 | 内容 |
|---|---|
| 编号 | Q1…Qn |
| 任务目标 | 一句话，动词开头 |
| 数学类型 | 优化 / 分类 / 预测 / 评价 / 仿真 / 统计 / 图 / 信号 |
| 输入 | 来自附件或上游的什么 |
| 输出 | 具体交付什么（数、表、方案、判别结果） |
| 约束 | 硬性限制 |
| 评价指标 | 用什么判断是否做好 |
| 依赖 | 依赖哪一问的什么结果 |

### 步骤 4 · 跨问联动链

明确写出各问之间**真实**的关系：

- **递进**：Q2 用 Q1 的模型或结果
- **并列**：各问独立，仅共用数据预处理
- **扩展**：Q3 是 Q2 增加条件后的版本
- **收敛**：后问综合前问结论

**不要预设"层层递进"。** 很多赛题的各问之间是并列或弱耦合，强行写成递进会导致后问编造依赖、前问被迫预留用不上的接口。

联动链还要明确**传递方式**：是沿用同一决策规则，还是锁定上游数值。这个选择必须在 Q2 定下并保持到 Qn，中途改变会造成前后对不上。

### 步骤 5 · 数据资产清单

| 字段 | 来源 | 类型 | 单位 | 缺失率 | 异常迹象 | 用于哪问 |
|---|---|---|---|---|---|---|

同时标注：哪些字段需要清洗、哪些字段口径存疑、哪些字段题面提到但附件没有。

### 步骤 5b · 数据交接包（AutoClaw 增强）

> 有附件数据时执行：**实际读取数据文件**生成「数据集说明」，
> 供 Stage 3 数据盘点与模型选型直接消费，也可单独发给其他 AI 协作。

- 说明内容：表结构 / 字段类型含义单位 / 关联字段 / 特殊结构 / 前 5 行 / 可运行读取代码
- 单独输出一段**可直接发送给其他 AI 的数据集描述**
- 纪律：必须实际读取、不猜字段、不虚构单位；无法确定处标注"推测"
- Agent 亲自读数时同样遵守此纪律

## 产物

`decision_log.json` 的 `stages.2`：

```
decomposition     子问任务卡数组
key_variables     关键变量及其来源
key_constraints   约束清单（含隐藏约束）
data_schema       数据资产清单
subproblem_dependency  依赖图与联动链
hidden_conditions 隐藏条件及依据
```

## 5 维评分

| 维度 | 判据 |
|---|---|
| `1_completeness` | 题面每句话是否被处理，有无漏问漏条件 |
| `2_hidden_conditions` | 是否识别出非字面条件并说明依据 |
| `3_linkage_clarity` | 跨问关系是否真实（非强行递进）、传递方式是否明确 |
| `4_data_inventory` | 数据清单是否覆盖字段/单位/缺失/异常 |
| `5_task_actionability` | 任务卡能否直接指导建模（输出与指标明确） |

## 检查清单

- [ ] 题面逐句处理完毕，无跳过的句子
- [ ] 每句都判断了是否隐含要求
- [ ] 隐藏条件写明了推导依据
- [ ] 每问都有明确的**输出形式**与**评价指标**
- [ ] 跨问关系经过判断，不是默认递进
- [ ] 传递方式（沿用规则 / 锁定数值）已明确
- [ ] 数据清单含单位与缺失率，不是只列字段名
- [ ] 题面提到但附件缺失的字段已被标注

## 常见失败

| 失败 | 表现 | 后果 |
|---|---|---|
| 跳读 | 只看问题段落，跳过背景与说明 | 漏掉关键约束，模型建错 |
| 强行递进 | 把并列问题写成层层深入 | 后问编造依赖，前问留无用接口 |
| 指标缺位 | 只说"分析关系"，没说用什么指标 | Stage 6 无法检验，Stage 9 被扣分 |
| 数据盲区 | 没核对附件字段与题面是否对得上 | 建模时才发现缺数据 |

## 退出条件

- `verdict = pass`，或
- `verdict = carryover`

进入 Stage 3 必须已确定 `qi_count`。
