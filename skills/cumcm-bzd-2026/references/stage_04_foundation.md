# Stage 4 · 基础构建（假设 · 符号 · 术语）

## 目标

建立全文共享的三张表：**假设表、符号表、术语表**。

这三张表是全文一致性的锚点。后面任何一处出现不一致（符号重复定义、假设没进模型、术语前后不同），都能追溯到本阶段。

## 时长

1–2 小时

## 输入

- 子问任务卡（Stage 2）
- 选定模型与论证（Stage 3）
- 数据资产清单

## 执行步骤

### 步骤 1 · 假设表

每条假设必须含三部分：

| 字段 | 要求 |
|---|---|
| 假设内容 | 一句话，可判定真伪 |
| **依据** | 来自数据特征、文献、题面还是常识 |
| **对模型的影响** | 进入哪个公式/算法/验证；若不成立会怎样 |

示例（合格）：

> 假设：同一孕妇的多次检测值存在个体特异的随机效应。
> 依据：附件中同一受试者的重复测量方差显著小于组间方差。
> 影响：需采用混合效应结构，否则标准误被低估、显著性检验失真。

示例（不合格）：

> 假设车辆匀速行驶。

孤立假设是 Stage 4 最常见的失败。没有依据的假设等于没写；没有影响说明的假设，读者无法判断它是否真的进入了模型。

**数量控制**：不以条数为目标。应覆盖所有实际进入模型的前提，删除没有进入公式、算法或验证的假设。常见合理区间 5–8 条。

**强假设必须写明验证方式**：正态性、独立性、平稳性、比例风险这类强假设，不能只写"假设成立"，要说明如何验证或在 Stage 6 验证。

### 步骤 2 · 符号表

采用三线表，三列：符号 | 含义 | 单位。

| 要求 | 说明 |
|---|---|
| 单位必填 | 有量纲的写单位，无量纲的写"—"或"无量纲" |
| 一符一义 | 同一符号全文只能表示一个含义 |
| 上下标区分 | 不同含义用下标（λ_decay、λ_LM），不靠上下文猜 |
| 收录范围 | 只收进入公式的符号，不收仅出现在文字中的词 |
| 篇幅 | 一般 15–30 个；过多说明符号设计混乱 |

**冲突检查**：逐个符号检查是否在正文不同位置表示不同含义。高频冲突点：

- 同一字母在公式中作变量、在文字中作计数
- 上下标在跨问后被复用但含义改变
- 向量/矩阵未用粗体或明确标注

**冲突修复**：改符号，不改含义。在已选定的模型上改符号的成本，远低于后期发现全文符号混乱。

### 步骤 3 · 术语表

统一全文表述，包括：

- 专业缩写的**首次出现全称**（中英文都要）
- 同一概念的统一叫法（不出现"检测时点/采样时刻/采血时间"混用）
- 变量命名与代码中的命名对应关系

**缩写规范**：首次出现写全称 + 缩写，如"受试者工作特征（Receiver Operating Characteristic, ROC）"，后文用缩写。

### 步骤 4 · 一致性预检

在写正文前先做一轮内部检查，避免错误流入 Stage 5：

- 假设表中的每条，是否能在 Stage 3 的模型中找到对应位置
- 符号表中的每个符号，是否会在 Stage 5 的公式中出现
- 术语表中的每个概念，是否在多个子问中都有明确所指
- 符号命名与代码变量是否可对应（便于 Stage 5 复查）

## 产物

`decision_log.json` 的 `stages.4`：

```
assumptions   假设数组（内容 / 依据 / 影响 / 验证方式）
symbols       符号表（符号 / 含义 / 单位）
terminology   术语表（中文 / 英文 / 缩写 / 首次出现位置）
consistency_check  一致性预检结果
```

同时输出 `templates/shared/` 风格的三张表，供 Stage 8 直接装配。

## 5 维评分

| 维度 | 判据 |
|---|---|
| `1_assumption_support` | 每条假设是否有依据与影响说明 |
| `2_assumption_coverage` | 是否覆盖所有实际进入模型的前提，无冗余 |
| `3_symbol_integrity` | 一符一义、单位完整、无冲突 |
| `4_terminology_uniformity` | 缩写全称、概念统一、与代码可对应 |
| `5_consistency_precheck` | 是否做了与模型/公式/代码的交叉预检 |

## 检查清单

- [ ] 每条假设有依据、有影响说明
- [ ] 强假设（正态/独立/平稳/PH）写明了验证方式
- [ ] 无"为了凑数"的假设
- [ ] 符号表含单位列，且全部填写
- [ ] 检查过一符多义与同义多符
- [ ] 收录的符号都会进入公式
- [ ] 所有缩写首次出现有中英文全称
- [ ] 术语与代码变量可对应
- [ ] 做过与 Stage 3 模型的交叉预检

## 常见失败

| 失败 | 表现 |
|---|---|
| 孤立假设 | 只写假设，不写依据和影响 |
| 假设膨胀 | 十几条相近假设堆在一起，多数没进模型 |
| 符号无单位 | 决策变量 x 不标单位，结果表无法核对量纲 |
| 缩写裸奔 | 首次出现直接写 ROC、AUC、LP |
| 术语漂移 | 同一概念在不同章节叫法不同 |

### 模型假设的三类来源

> 来源：PDF L870

三、模型假设的来源
1. 题目明确给出的假设
题目已经规定的条件应准确保留，例如“城市人口为100万”“设备处于额定状态”“某
参数在研究周期内保持不变”。
2. 根据题目合理推出的假设
题目未直接说明，但可以依据研究情境、常识或附件信息合理推导，例如在正常运
营研究中排除战争、重大灾害等极端事件。
3. 具体模型所必需的假设
为了满足模型结构或算法条件而设置，例如线性关系、泊松到达、均匀混合、平稳
序列等。这类假设应尽量由数据检验、机理分析、领域常识或文献支持。

### 不同类型问题的假设示例

> 来源：PDF L944

七、不同类型问题的假设示例
1. 预测类问题
 假设经清洗后的历史数据能够反映研究对象的主要变化规律。
 假设预测期内不发生改变原有发展机制的重大突发事件。
 假设历史数据中识别出的主要关系在预测期内具有一定延续性。
 假设不同来源数据经口径统一后具有可比性。
 假设随机扰动的均值为0，不造成长期系统性偏差。
2. 综合评价问题
 假设所选指标能够从题目要求的维度反映评价对象的主要特征。
 假设指标经标准化后具有可比性。
 假设各评价对象处于相同或可比的评价环境。
 假设指标间的信息重复可通过相关性分析或降维方法控制。
错误写法：“假设所选指标能够全面、准确地评价研究对象。”这相当于提前假定模型正确，应在后
文通过权重对比、敏感性分析或结果验证进行检验。
3. 优化问题
 假设决策周期内资源总量和主要约束条件已知。
 假设各项成本按照统一口径计算。
 假设执行过程不存在未建模的额外资源损耗。
 假设同一决策周期内单位成本保持不变。
 假设所有决策变量均满足题目规定的可行范围。
4. 交通与路径问题
 在单次任务周期内，道路网络结构不发生变化。
 除题目明确考虑的拥堵因素外，忽略临时交通管制和重大事故。
 车辆按照规划路径运行，不发生无任务要求的中途绕行。
 若车辆尺寸相对于道路尺度可忽略，则将车辆视为质点。
5. 物理机理问题
 假设材料均匀且各向同性。
 假设系统与外界的非目标能量交换可以忽略。
 假设测量仪器的随机误差处于允许范围。
 假设研究区间内相关物理参数保持恒定。
 忽略对主要物理过程影响较小的高阶效应。
6. 新能源汽车问题
 假设产销量、保有量、能源消费和排放数据来源可靠，经口径统一后具有可比性。
 除政策影响问题外，在基础趋势模型中不考虑战争、重大灾害等极端事件造成的结
构性冲击。
 在基准情景下，历史数据反映的主要发展机制在预测期内具有延续性；政策变化通
过单独情景参数刻画。
 假设同类车辆在相同使用条件下的平均能耗和平均行驶里程具有代表性。
 生态环境模型中的排放因子采用统一核算口径，并考虑电力生产端与车辆使用端的
