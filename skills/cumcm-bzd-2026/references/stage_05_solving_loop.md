# Stage 5 · 递归求解 Q1…Qn

## 目标

按子问逐个完成建模、求解、结果解读与可视化，并对每个子问单独记分。

本阶段是全文篇幅与工作量的主体，也是唯一支持**按子问局部返工**的阶段。

## 时长

按题目分配。以 30 页正文为参考：

| 板块 | 建议篇幅 |
|---|---|
| 前置章节（问题重述、分析、假设、符号） | 3–4 页 |
| 公共数据处理 | 2–3 页（仅多问共用数据时集中设置） |
| 问题一 | 6–7 页 |
| 问题二 | 6–7 页 |
| 问题三 | 8–9 页（若为综合问题或分值更高应增加） |
| 收尾章节（评价、推广、参考文献、AI 声明） | 2–3 页 |

篇幅原则：与分值、重要程度、模型复杂度和检验需求相匹配。**不能让简单的数据处理挤占主要模型，也不能让最后一个重要问题只剩一两页。**

## 输入

- 子问任务卡与依赖图（Stage 2）
- 选定模型与论证（Stage 3）
- 假设表、符号表、术语表（Stage 4）
- 附件数据

## 每问的固定流程

对每个 Qi 依次执行五步，完成后立即评分。不要全部做完再统一评——那样返工成本会成倍上升。

### 步骤 1 · 探索与前置依据

在建模前先做探索分析，产出进入正文的证据：

- 数据分布、相关结构、异常迹象
- 决定模型形式的数据特征（非线性？时序？删失？不平衡？）
- 关键变量的取值范围与量纲

### 步骤 2 · 模型建立

六项要求，缺一不可：

1. **定义变量与参数**：决策变量、状态变量、输入、输出，含集合、下标、单位和取值范围
2. **目标函数**：明确写出，说明各项含义与量纲
3. **约束条件**：每个约束动词对应一个约束方程
4. **符号首次出现需解释**：即使符号表已列出
5. **针对性**：删除赛题背景后，本段不能原封不动用于其他题
6. **模型修改后同步清理旧变量**

**约束必须写成数学式。** 只写"无人机起飞不得早于包裹到货"而不写 $t^{dep}_r \ge \max t^{arr}_p$，读者无法判断约束集是否闭合。时序耦合尤其不能只停留在文字。

### 步骤 3 · 求解

| 要求 | 说明 |
|---|---|
| 代码可追溯 | 关键步骤写清意图、参数，及对应正文章节与公式编号 |
| 随机性固定 | 固定并记录种子、软件版本、采样设置 |
| sanity check | 边界、守恒、量纲或已知解检查，保存输入与预期结果 |
| 量纲与数量级 | 求解后立即检查，避免"优化得到 −10⁹ 但题目问百分比" |
| 时间预算 | 超时先降问题规模，不硬等 |

**代码注释语言**以团队可维护和提交规范为准。

### 步骤 4 · 结果解读

**禁止只报数字。** 每个结果都要回答"这意味着什么"：

| 不合格 | 合格 |
|---|---|
| 得到 X = 12.3 | 得到 X = 12.3，意味着每天最多调度 12 辆车，与同类运营公司 10–15 辆的区间一致 |

同时必须**与基线对比**：定义可比的基线方案，保持相同数据切分、预算和指标。没有合理基线时应说明原因，并给出其他验证证据。

**表内每个指标必须回指目标函数的一个符号。** 表格里冒出一个正文找不到定义的指标，读者无法核对它从何而来。

### 步骤 5 · 可视化

| 要求 | 说明 |
|---|---|
| 图型匹配任务 | 趋势用折线、比较用柱状、关系用散点、分布用箱线 |
| 可读性 | 检查灰度、色盲、缩放后的可读性 |
| 宽度 | 单图约版心 70%，多图并排合计也约 70% |
| 数值真实 | 图中数值必须来自真实计算结果 |

流程清楚时不必重复画流程图；结果适合精确比较时优先用表而非图。

## 5 维评分

每问完成后立即评分（5 维，1–10），随后可聚合：

| 维度 | 判据 |
|---|---|
| `1_subproblem_completeness` | 任务卡要求的输出是否全部交付 |
| `2_model_rigor` | 变量/目标/约束是否完整，约束是否数学化 |
| `3_result_interpretation` | 是否解读含义并与基线对比 |
| `4_figure_quality` | 图型是否匹配、数值是否真实、可读性 |
| `5_cross_reference_chain` | 是否正确引用上游结果，口径是否一致 |

评分后写入 `scores.5_per_qi`（含 `qi_id`），并更新 `qi_status`。

全部完成后聚合：

```bash
python <wf>/scripts/score_artifact.py --mode aggregate_qi \
  --qi-results <cwd>/state/qi_results.json \
  --decision-log <cwd>/state/decision_log.json
```

聚合会重算 `qi_status`、`review_qis`、`refine_qis` 与最终 verdict。

## 局部返工机制

| 情形 | verdict | 行为 |
|---|---|---|
| 某 Qi 的 min < 7，其他已 pass | `refine_partial` | **只重跑该 Qi**，不动其他 |
| 某 Qi 单独弱但全 stage 仍 pass | `pass_with_review` | 进 Stage 6，L2 必读该 Qi |
| 任一 Qi 有 high-severity issue | `block` | 该 Qi 标记 block |

**局部错误优先局部修复。** 默认推翻全部结果是最贵的选择，且往往引入新错误。

返工后需回检下游：若 Qi 的结果被 Qj 使用，Qi 改动后必须重跑 Qj 并核对口径。

## AI 使用提示

AI 可用于：程序框架建议、局部代码生成、代码调试、运行效率优化、绘图代码辅助。

每条使用都需说明：最终算法选择依据、参数设定、哪些代码结构来自 AI 建议、参赛队如何验证其正确性。

**禁止 AI 直接生成最终数值。** 检验数值、精度结果必须来自真实程序输出。

## 检查清单

每问完成即查：

- [ ] 变量、目标函数、约束全部写出，约束是数学式
- [ ] 删掉赛题背景后，建模段不能用于其他题
- [ ] 固定了随机种子并已记录
- [ ] 做过 sanity check 与量纲/数量级检查
- [ ] 每个结果都有解读，不是只报数字
- [ ] 与基线做过对比
- [ ] 表中每个指标可回指目标函数符号
- [ ] 图中数值来自真实计算
- [ ] 引用上游结果时口径一致
- [ ] 代码注释含正文章节与公式编号回指

## 常见失败

| 失败 | 表现 |
|---|---|
| 全链路贪心无参照 | 每步局部最优，无最优性证据，结论只有可行解 |
| 只报数字 | "得到 X = 12.3"，无解读无对比 |
| 约束停在文字 | 时序耦合没有对应方程 |
| 图表与正文不符 | 图中数值与结果表对不上 |
| 篇幅失衡 | 数据处理占 8 页，核心问题只剩 3 页 |
