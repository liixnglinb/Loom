# CUMCM 9 阶段论文全流程 · BZD 2026 模板版（v1.0）

把 72 小时竞赛组织成 **9 个可恢复、可检查、可局部返工的阶段**。用户回答编号判断，Agent 负责状态维护、
规则核对、脚本调用与产物组织。每个阶段以**质量门**收口（风险按 P0-P3 定级，P0 未清零不得进入下一阶段），
并以**加权评分**（`config/dim_weights.json`）驱动 verdict 收敛。

**双审查（本 Skill 的必胜机制）**：提交前安排**两次彼此独立**的全面审查——
**阶段 7 · 全面审查 I（章节专项自查）** 按各章规则/自查清单自下而上逐章体检；
**阶段 8 · 全面审查 II（综合评审）** 切换到陌生评委视角、冻结 rubic、90% 封顶，自上而下整体打分。
两轮不共享中间结论，避免锚定；任何 P0/P1 未闭环不放行。

## 状态持久化（decision\_log.json）

初始化：复制 `templates/shared/decision_log.json` 到 `<cwd>/state/`，写入 competition / task\_type / mode。
关键字段：

- root：`competition / task_type / mode / current_stage / budget / events / compliance`

- `compliance.ruleset`：competition\_year / verified\_at / official\_urls（三重门落点）

- `compliance.ai_usage`：null=未核对；\[]=确认未用；数组=逐条记录（工具/版本/日期/环节/用途/采纳/人工核验）

- `stages.1-9`：status / artifacts / key\_decisions / rejected\_alternatives / open\_issues

- `scores.<n>`：历次评分、verdict 与 P0-P3 计数（5 维分 + `dim_weights` 加权 weighted\_mean）

- 对账纪律：`open_issues` 不静默丢弃，后续每个质量门必须显示其状态（已解决/仍开放）。

## 质量门协议（通用收口）

每阶段末尾以严苛评委视角执行质量门，输出并持久化到 `scores.<n>`：

```json
{"stage_id": 3, "iteration": 1,
 "risks": [{"level": "P0|P1|P2|P3", "where": "§5.2 公式(5.3)", "problem": "≤40字",
            "evidence": "位置/原文", "fix": "≤50字可执行"}],
 "counts": {"P0": 0, "P1": 1, "P2": 2, "P3": 0},
 "verdict": "pass|pass_early|pass_with_review|refine|refine_partial|carryover|block"}
```

**风险定级**：

- **P0** 直接致命：虚构结果/文献/检验；身份信息泄露；复现失败或结果与正文不符；AI 声明与实际矛盾；违反当届硬性规则

- **P1** 关键缺失：任务遗漏；检验缺失；联动断裂；必要披露缺失

- **P2** 一致性问题：符号漂移；图表正文不一致；口径/单位冲突

- **P3** 表达与格式：标点/格式/措辞

**verdict 收敛准则**（与 `scripts/score_artifact.py` 一致；先 P0-P3 后加权分，顺序不可变）：

1. 任一 P0 → `block`：暂停并编号问答处理；不提供"强制放行"。
2. 任一 P1 → `refine` 或 `block`：定向修复（只改问题位置）后重跑受影响项，iteration+1（cap 3；第 3 次不过停下与用户确认）。
3. 加权分：`weighted_mean` = Σ(sᵢ×wᵢ)/Σwᵢ，权重取 `config/dim_weights.json[task_type][stage]`，clamp \[0.7,1.5]；`raw_min≥9 且 weighted_mean≥9` → `pass_early`；`raw_min≥7 且 weighted_mean≥8` → `pass`。
4. 仅 P2/P3 → `pass_with_fix`：进下一阶段，issues 挂入 open\_issues 闭环。
5. stage 5 特判：`refine_partial`（仅重跑该 Qi）；`pass_with_review`（mark\_for\_review 交 L2）。
6. `carryover`（iter=3 仍 refine）：带标记进下一阶段由 L2 处理。

**每阶段三个固定自检问**：哪里最可能被评委挑？哪些主张还没有证据定位？哪里存在"看起来完成了"的偷懒？

# 阶段 1 · 启动与题面解析

**时长** 2-4h ｜ **加载** `stage_01`、`stage_02` ｜ **三重门 #1**

目标：环境/角色/选题/规则基线就绪，并把题面从竞赛散文翻译成**可执行建模语义**。

1. **启动字段**（一轮编号问答，已有不重复问；"让我决定"兜底）：竞赛/题号/队员擅长/截止/题面附件路径。题面未公布 → 完成后置 `sub_status=waiting_for_problem` 等待，不进入阶段 2。
2. **环境预检**：`python <skill>/scripts/doctor.py --workspace <cwd>`；不通过不进下一步。
3. **角色分工**：建模主/编程主/写作主，互相备岗；每人一句"我对这道题最大的顾虑"。
4. **规则基线核对**：读 `references/rules_baseline.md`，打开当届官方链接逐项核对（页数/起始页/匿名/承诺书/目录/AI 披露），写 `compliance.ruleset` + `verified_at`（三重门 #1）。
5. **多题比较选题**：四维打分（资源/能力/区分度/失败风险）；写下 `selected/rationale/rejected_alternatives/risks`；改题需新证据进 events。
6. **题面翻译台账**（本阶段核心，按 `stage_02` 步骤 1b）：

   - 定位锚点 → 一句完整原句一个编号单元（B01/Q2-04），全文稳定

   - **十类角色标注**（context/entity/definition/mechanism/given/constraint/task/objective/validation/deliverable）

   - **8 列覆盖台账**：编号|题干原句|翻译|明示条件|隐含信号|联动|漏读后果|后文证据——实质单元数=台账行数

   - 翻译六问、**量词保真**（不考虑/仅/至多/至少/必须/不得 强度原样保留；数字绑定实体与单位）、最易漏读句 5-12 条

   - 术语与口径表（区分题面事实与模型假设）、逐问输入-任务-输出表、歧义处理（不虚构官方解读）

   - 有附件 → **数据交接包**：实际读取生成数据集说明，单独输出可发给其他 AI 的描述
7. 退出条件：覆盖审计 100%、联动链完整、质量门通过（无 P0/P1）。

# 阶段 2 · 建模策略与模型选型

**时长** 2-4h ｜ **加载** `stage_03`、`model_fit_rubric.md`、`rules_baseline.md`

目标：先建全题任务图，再谈单个模型；产出贯穿全文的主线 + 每问证据充分的选择表。

1. **任务角色分类**：每问标 foundation/estimation/explanation/prediction/extension/optimization/decision/validation；对照六种跨问架构预判联动。
2. **数据盘点**：结构/类型/样本量/缺失异常口径；预处理方法必须对应实际数据问题（禁止无依据罗列方法）。
3. **数模字典选型**：每问候选 ≥2 真不同；查字典（`scripts/query_model_dict.py`，外部字典按 `model_fit_rubric` 许可约束只读引用）得到适用场景/数据要求/假设/检验；四级判定（合适/有条件合适/不合适/证据不足待人工复核）；求解器名不算模型。
4. **比较与推荐**：比较表逐列可执行；推荐说明契合/数据/代价/输出/可解释/成本/与后问兼容；给出备选切换时机。
5. **全文统一口径表 v1**：共享符号/指标/变量/参数/单位/坐标/预处理规则/目标/约束/评价指标——一次定义全文复用。
6. **创新方向**：每条 = 改动组件+实现步骤+可测对照+风险备选；"使用遗传算法/模型融合/更多可视化"不算创新。
7. **toy demo**：每问主模型最小可行示例（可行性先于优化；toy 与失败原因写入 state）。
8. **断链检查**：参数/坐标/单位/目标跨问兼容；防特征泄漏与重复计数；选定 `task_type`（影响后续评分权重）。
9. 退出条件：候选 ≥2 且接口列非空；断链清单为空或逐条登记；toy 全过或失败原因已登记。

# 阶段 3 · 建模执行

**时长** 30-45h（按问分配）｜ **加载** `stage_05`、`references/template_library/chapter05_model_solving.md`、`prompt_library.md`（第五章板块）

目标：每个子问题跑完 mini-pipeline：**思路 → 建立 → 求解 → 结果 → 检验 → 灵敏度**。

1. **篇幅规划**：正文 ≤30 页：前置 3-4 页；公共数据 2-3 页（多问共用才集中设章）；每问 6-9 页；收尾 2-3 页。
2. **数据预处理**（按位置判定）：七要素——来源/样本量字段时间范围/缺失异常重复的量化/处理方法与理由/处理数量/前后统计对比/标准化编码划分。禁止"对数据做了处理"式空话。
3. **逐问六步**（每问 A-F）：

   - A 建模思路与选型（目标/已知/输出/数学类型四件套；删除赛题背景后仍通用的段落=未针对本题，重写）

   - B 模型建立（定义变量参数含单位取值；公式前写依据、后释含义；参数来源四类；每条约束写现实含义；**优化模型集中表达**"综上建立如下模型"+目标+约束+变量一个公式组）

   - C 模型求解（算法名称思想理由；输入输出关键步骤；初值参数最大迭代停止条件软件版本；智能算法另加编码/适应度/算子/种群参数/多次运行收敛曲线/随机种子；完整代码进附录正文留伪代码）

   - D 结果呈现（逐项回答不漏；数值方案排名预测标单位口径时间样本范围；解释现实规律；异常归因；提炼关键数值不逐个复读图表）

   - E 模型检验（按类型匹配指标：预测→MAE/RMSE/MAPE/R²+残差；分类→混淆矩阵/准确率/召回/F1/AUC；聚类→轮廓/CH/DB；优化→约束满足率/最优性差距/重复运行；评价→排名一致性/权重扰动。必须给指标数值+判定标准+对照；训练集拟合不算验证）

   - F 灵敏度分析（只对决定结论/参数依赖强/来源不确定的主模型：选参→基准与范围步长→固定其余逐次重解→参数-结果关系图→敏感参数与稳定区间→结论是否改变；S=(ΔY/Y)/(ΔX/X)；多因素用正交/响应面/网格/蒙特卡洛/Sobol；禁止全部参数机械 ±10%）
4. **跨问联动检查**：递进问必须显式前问输出→后问在哪接口调用→单位时间转换→误差传播；"只写基于问题一而实际重算"=假联动（P1）。
5. **图表纪律**：表承数值、图承趋势；同一组结果只用一种主表达；图表三有（前引/中引用/后解释）；正文表格 ≤15 行；单图约 70% 文本宽。
6. **逐问写作落地**（代码转正文见 `stage_08` 增强段；结果分析段 180-220 字连续段落，直接入正文）。
7. 退出条件：六步齐备；检验匹配表量化；无假联动；无 P0（虚构/复现黑洞）。

# 阶段 4 · 稳健性总检验

**时长** 3-5h ｜ **加载** `stage_06`、`references/template_library/chapter05_model_solving.md`（灵敏度/稳健性/误差分析三节）

目标：核心结论在合理不确定性下是否仍然成立？明确"已验证/未验证/何时失效"。

1. **全文验证矩阵**：每个影响结论的主张 → 独立校验路由（正向重构/守恒/单位不变性/留出验证/残差显著性/区间覆盖/噪声-参数-预处理-分组灵敏度/solver gap 多种子/高保真重评粗模型最优）。每主张至少一项匹配风险的校验，不凑数量。
2. **稳健性分析**：改变输入/样本规模/异常处理/权重/初值/假设 → 趋势/排序/最优方案是否不变；量化稳定区间。
3. **误差传播链**：前问误差如何进入后问输入并影响结论；给平均/最大误差或置信区间；禁止"误差较小"。
4. **失败边界**：使解释或最优方案失效的条件组合；未验证风险及其影响。
5. **断链清零复核**：阶段 2 登记的断链闭环；代理最优回原系统重评；不可行解排查。
6. 退出条件：验证矩阵每行有证据；稳定区间量化；失败边界明确；championship 模式对最弱主张追加独立复核。

# 阶段 5 · 章节写作

**时长** 4-6h（前置章可与阶段 3 滚动并行）｜ **加载** `stage_08`、`writing_spec.md`、`references/template_library/chapter01_restatement.md`/`chapter02_analysis.md`/`chapter03_assumptions.md`/`chapter04_symbols.md`/`chapter06_evaluation.md`、`prompt_library.md`（第一\~四章/第六章板块）

`stage_08`（AutoClaw 增强段）与 `references/template_library/`。要点：

# 阶段 6 · 摘要与首页（全部完成后才写）

**时长** 2-3h ｜ **加载** `references/template_library/abstract_chapter.md` ｜ **三重门 #2**

1. **题目**：基于【主要模型/方法】的【研究对象/核心问题】研究；准确具体简洁；主模型或最具创新模型进标题；禁谐音梗/方法堆砌。
2. **摘要**（800-1000 字一页内，第三人称）：**虎头**（背景一句+问题一句，3-4 行，不堆技术细节）→ **猪肚**（一问一段：任务→数据→模型及数学类型→建模思想→算法→关键量化结果→检验结论；承接语按真实关系，禁止预设层层递进）→ **豹尾**（真实创新+检验表现+推广+局限；正文没有的检验不得虚构）。
3. **关键词** 4-6 个：问题词/模型词/算法创新词三方向各一，禁宽泛词/软件名/凑数。
4. **15 项摘要自查清单**与**独立阅读性第一关**（非本领域者仅凭摘要能说出问题/模型/结果）；用 `abstract_chapter.md` 的通用成稿模板与问题一\~四段模板。
5. **三重门 #2**：复核当届摘要页与格式规范（页码从摘要页起、页脚居中、无身份信息），更新 `verified_at`。
6. 退出条件：独立阅读性三要素齐全；一页内；与正文零冲突。

# 阶段 7 · 全面审查 I：章节专项自查（双审查之一）

**时长** 3-5h ｜ **加载** `references/anti_patterns.md`、`references/template_library/*`（各章自查清单）、「26 项 AI 合规清单」（见下）

自下而上、按章节规则逐章体检（不重写，只定向修复）：

1. **摘要**：15 项自查 + 独立阅读性。
2. **问题重述**：题意保持（任务/条件/数字/单位/约束/附件/输出形式）+ 章节边界（分析/模型/算法/公式/结果不得漏进）+ 综述证据与虚构风险（文献四验）。
3. **问题分析**：任务覆盖映射 + 跨问联动真实性 + 数据依据 + 章节越界 + 框架图一致性。
4. **模型假设**：来源/合理性/必要性/依据逐条；遗漏候选；强假设验证要求；假设-后文对应。
5. **符号说明**：正文↔符号表双向核对（缺失/冗余/多义/大小写上下标漂移）+ 单位 + 首次定义 + 三线表版式。
6. **模型建立与求解**：任务-响应映射表 + 数据预处理 + 选型针对性 + 参数目标约束 + 算法可复现 + 结果图表 + 检验匹配 + 灵敏度诊断 + 跨问联动与误差传播。
7. **模型评价**：优点有证据/不足带边界/改进对应/推广有对象；与摘要结果检验一致。
8. **参考文献与附录**：引用↔文末一一对应 + 格式统一（GB/T 7714）+ 数量 5-15 + **匿名性扫描**（正文/代码注释/路径/截图/文档属性/文件名）。
9. **AI 披露**：声明↔详情↔真实台账一致；无"只写润色实际建模"式弱化。
10. **26 项 AI 合规清单**（2026 六维度，逐项 `合格/存在问题/待核实`，无空项；死亡项=AI 主导核心建模/虚构数据文献/声明矛盾 → P0 block）：

    - A AI 新规合规 4（声明位置/详情四要素/台账逐条/不进参考文献）

    - B AI 幻觉与真实性 4（无虚构数值/文献四验/数据如实/AI 不补造）

    - C 建模逻辑与题意 5（任务覆盖/选型论证/假设一致/联动真实/口径统一）

    - D 求解合理 3（可复现/合理性审查/检验匹配）

    - E 官方写作规范 6（篇幅/匿名/章节目录/摘要/参考文献/图表编号）

    - F 排版与页数 4（格式一致/无占位符/页数上限/附录支撑材料）

回修协议：P0/P1 → 立即定向修复 → 重跑受影响自查项 → 循环至 P0=P1=0；P2/P3 → 修复或记录接受理由。**没有问题的章节明确写"合理"，不为显得严格而虚构缺陷。**

退出条件：P0=0 且 P1=0；26 项清单无空项；全文符号检索核对完成。

# 阶段 8 · 全面审查 II：综合评审（双审查之二）

**时长** 2-4h ｜ **加载** `feedback_l1_critic.md`、`rubrics.md`

切换"陌生评委"视角，自上而下整体打分；不共享阶段 7 的中间结论。

1. **隔离声明**：本评审只依据"当届赛题 + 当前论文"，不使用历史解题思路/偏好/结论。
2. **先读题分解任务 → 制定并冻结本题专用百分制 rubric**（写 `stages.9.rubric_frozen_at` 时间戳）→ **然后才读论文**（防先入为主）。参考配比：摘要 10、格式 10、模型假设+建立+求解 70-75、其余 5-10。
3. **90% 封顶**：每数值维度 ≤ 权重×0.9（满分理论上限 90/100）；封顶标注"评委满分保留"，不算论文缺陷，释放空间不加回。
4. **逐维评分**：每个给分/扣分点带位置证据（页码/公式号/图表号）。
5. **评委式评价**：一段总评 + 最有分量优缺点（带位置）+ **创新盲区提示**（非常规路线可能被 AI 评审低估）。
6. **优先修改建议** 3-5 条按期望得分增益排序；不承诺奖项、不预测获奖概率。
7. **红队攻击**（championship）：反方评委攻击最弱章节 30 分钟，产出问题并入回修协议。

退出条件：rubric 冻结时间戳早于读稿；无证据不给分；修改建议全部按 P0-P3 路由到对应阶段回修。

# 阶段 9 · 终稿装配与合规出库

1. **全文组装**（顺序固定）：承诺书 → 编号专用页 → 摘要专用页（第一页起编页码）→ 正文（重述→分析→假设→符号→各问建立求解→模型评价）→ **AI 工具使用声明** → 参考文献 → 附录（A 文件列表/B 环境/C 源程序）。**正文不设目录**。

4. **最终 PDF 目检**：首页、公式密集页、宽表、图密集页、参考文献、附录逐页过；无 `??`、无越界。
5. **三重门 #3**：出库前最后核对当届官方通知，更新 `verified_at`；写 `submission_ready=true`。

退出条件：合规门全绿；26 项无空项无死亡项；PDF 存在且目检通过；支撑包完整匿名。
