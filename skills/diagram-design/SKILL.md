# Diagram Design — 图表设计系统规范（本地化）

> 当需要绘制**架构图、流程图、时序图、状态机、ER、泳道、树状等示意类图**时，本文是**设计规范最高权威**：
> 结构忠实逻辑、视觉以"编辑级"为标准（不做"AI 味"图）。执行链路（HTML 生成 → 截图转 PDF → 几何/视觉质检 →
> `latex_includes.tex` 对账）由 `paper-figure-html` 负责；本 skill 只提供**设计与选型钢筋**，两者配合使用。

## 0. 哲学（先过脑子，再动手）

1. **最高级的动作通常是删除**：两个总在一起的节点=一个节点；能从布局看出的关系就删掉那条线。
2. **目标密度 4/10**：够表达完整即可，别密到需要"看图指南"。节点 >9 就拆成两张（总览 + 细节）。
3. 动手前自问：读者从这张图获得的信息会超过一段好文字/一张 3 列表格吗？不会就别画。

## 1. 选型（按要表达的内容定类型，不按"哪个好看"）

| 要表达       | 用          | 要点                |
| --------- | ---------- | ----------------- |
| 系统组件+连接   | **架构图**    | 分层/分组框，层间连线带协议名   |
| 决策逻辑/分支   | **流程图**    | 菱形判断+矩形步骤，一条主链    |
| 时序消息/协议   | **时序图**    | 参与者竖线+消息箭头，时间自上而下 |
| 状态/生命周期   | **状态机**    | 圆角状态+事件标签，≤7 状态   |
| 实体+字段+关系  | **ER 图**   | 表框+外键连线           |
| 跨角色流程     | **泳道图**    | 泳道=角色，交接箭头过泳道     |
| 事件按时间排    | **时间线**    | 横轴时间，事件点+标签       |
| 双因素定位/优先级 | **象限图**    | 2×2 或 2×3，轴线带标签   |
| 父子/从属     | **树**      | 自上而下，层级对齐         |
| 组织/汇报关系   | **组织图**    | 同树，注意角色标题         |
| 抽象层级堆叠    | **分层栈**    | 横向条带堆叠，每层一概念      |
| 集合交叠      | **Venn**   | ≤4 集              |
| 分级/转化漏斗   | **金字塔/漏斗** | 层级宽度=数量/比例        |
| 任务/排程     | **甘特图**    | 横条区间+关键路径         |
| 量分合/流向    | **桑基**     | 带宽=流量，用量克制        |
| 依赖关系      | **依赖图**    | 节点+方向边，标注 fan-in  |
| 类/继承/组合   | **UML 类图** | 类框三段式             |
| 全流程数据交接   | **数据流**    | 阶段+角色+数据资产        |

选型硬规则：

- 两张类型都行 → 取**主轴**类型，不要杂交两种布局语法。

- 3 列表格说得清 → 用表格，不画。

- 超出复杂度预算（§5）→ 拆 overview + detail。

## 2. 语义色系统（配色只有一个事实源）

用语义角色，**不硬编码 hex**：

| 角色             | 用途                                         |
| -------------- | ------------------------------------------ |
| `paper`        | 页面/容器背景（HTML 引擎下画布必须 `transparent`，融入论文白底） |
| `ink`          | 主文字 / 主描边（近黑，别带色相）                         |
| `muted / soft` | 次要文字、默认箭头、副标签                              |
| `rule`         | 发丝分隔线（1px）                                 |
| `accent`       | 焦点（**最多 1-2 个元素**）                         |
| `link`         | HTTP/API 调用、外部系统箭头                         |

**焦点规则（硬）**：`accent` 只上 1-2 个元素。其余一律 `ink/muted/soft`。想给 4 个东西上色 = 还没想清楚谁才是焦点。

### 节点类型 → 填充/描边 标准表（按语义分类，不是"每类一个彩块"）

| 类型            | 填充         | 描边       |
| ------------- | ---------- | -------- |
| **焦点**（1-2 个） | accent 浅底  | accent   |
| 后端 / 组件 / 步骤  | 白          | ink      |
| 存储 / 状态 / 数据  | ink\@5% 灰底 | muted    |
| 外部 / 云端依赖     | ink\@3%    | ink\@30% |
| 输入 / 用户       | muted\@10% | soft     |
| 可选 / 异步       | ink\@2%    | 虚线 4,3   |

## 3. 排版（名称与技术内容分字体）

- **节点名/人类可读标签**：无衬线（微软雅黑/系统 sans），12px，600，4–10 字+一行副标题。

- **技术子标签**（端口、命令、URL、单位）：等宽（Consolas/系统 mono），9px。

- **标题**：论文图内**不写标题**（LaTeX `\caption{}` 管）。

- **旁注/引语**：衬线斜体（可选，中文环境用楷体替代或省略）。

- **等宽字体只用于技术内容**，禁止把 mono 当"开发风"通用字体。

## 4. 几何与造型（"不像 AI 生成"的细节）

- **发丝描边**：边框 1px，`rule` 角色；**禁止阴影**（阴影 out，边框 in）。

- **圆角 ≤ 10px**（默认 6–10px 或 0），禁止 `rounded-2xl` 大圆角。

- **4px 网格**：所有坐标、宽度、间距能被 4 整除（防漂移、防"差一点"视觉）。

- **布局**：行/列一律 `display:grid`（自动对齐、防错位），禁止手排 absolute 挪节点；多行多列必须行列对齐成线。

- **画布透明**：整图不铺底色块；节点自身可浅填充、文字 `ink` 近黑。

- **密度平衡**：一节点塞两行以上长句 → 拆节点或移副标题。宁可多一个节点，不要一句长文。

## 5. 复杂度预算（每张图硬上限，超出即拆）

| 项            | 上限     |
| ------------ | ------ |
| 节点数          | **9**  |
| 箭头/连线        | **12** |
| 焦点（accent）元素 | **2**  |
| 泳道（泳道图）      | 5      |
| 时序生命线        | 5      |
| ER 实体        | 8      |
| 嵌套层级         | 6      |
| 树深度          | 4      |
| 分层栈层数        | 6      |
| 旁注/标注        | 2      |

## 6. 反模式（出现即"AI 味"信号，禁止）

- 暗色底 + 青/紫光晕（假装"科技感"，实际没设计）

- 全部节点同一个盒子样式（抹平层级）

- **图例飘在图内**（碰撞节点）→ 放图下方注释行

- 箭头标签无文字遮盖（墨迹穿过线条就废）→ 标签放胶囊/白底

- 阴影 / 大圆角

- 焦点色染所有"重要"节点 → 焦点 ≤2

- 借鉴 Mermaid 自动布局（继承它的稀疏布线而非编辑级排版）

- 连线互相穿透/穿过非端点盒子

## 7. 箭头约定

- 默认：实线 `→`（内部流转）

- 焦点：accent 描边（主链路强调）

- 外部调用：link 蓝（HTTP/API）

- 可选/异步/返回：虚线

- 强强调：粗线（极克制）

## 8. 出图前删除测试（taste gate，每张必过）

**选型**

- [ ] 类型与内容匹配（§1 表）？表格/段落能否替代？
  **删除**

- [ ] 能删某个节点吗（读者还懂）？

- [ ] 能合并两节点吗（总在一起）？

- [ ] 能删某条连线吗（布局已暗示）？

- [ ] 能删某个标签吗（颜色/形状已表达）？
  **信号**

- [ ] accent 用在 ≤2 元素？

- [ ] 图例覆盖所有用到的类型、且无多余？

- [ ] 在 §5 复杂度预算内？
  **技术**

- [ ] grid 对齐、无绝对定位漂移？

- [ ] 所有坐标/间距 4px 整除？

- [ ] 无阴影、圆角 ≤10px、画布透明？

- [ ] 节点名称无衬线，技术子标签等宽？

- [ ] 图内无标题（交 caption）？

## 9. 与执行链配合（本 skill 不独立产出）

1. 设计稿即**自包含 HTML**（inline CSS，不引外网），图内字体用系统字体。
2. 由 `paper-figure-html` 流程执行：`screenshot_capture.py --file xxx.html --out xxx.pdf --format pdf`（矢量单页无白边）。
3. 全部图进 `figures/latex_includes.tex` 并跑 `fig_include_size.py` 规整宽度。
4. manifest 规划了就必须逐个产出；本规范只决定"长什么样"，"产不产、几点产"由流程管。
