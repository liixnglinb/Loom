# 反模式清单 (anti_patterns)

> 57 个操作性检查项，从公开论文差异、常见失败案例与维护者复盘中归纳。它们不是官方评分权重或获奖因果规律；Stage 9 用它们做启发式终审。每条配 (a) 现象 (b) 风险 (c) 修复路径。

---

## A. 摘要类 (高影响)

### A1. 摘要无定量结果
- 现象: "本文得到了较好的结果" / "求解效果良好"
- 风险: 读者无法核对核心结论，也看不出结果与题目任务的对应关系
- 修复: 在结果确有计算或实验支撑时，写出指标、单位、场景和比较基线，例如“在场景 A 下得到配比 (0.42, 0.31, 0.27)，相对已定义基线误差降低 1.8 个百分点”

### A2. 摘要信息组织混乱
- 现象: 背景、方法、结果与边界混在一起，或段落顺序无法对应题目任务
- 修复: 按“问题与任务 → 方法 → 主要结果 → 验证与边界”的阅读顺序组织；可以合并或拆分段落，不追求固定段数

### A3. 摘要与论文内容不符
- 现象: 摘要说用了 LSTM,正文却是 BP
- 修复: 摘要定稿前逐项回指正文的模型、数据版本、结果表和限制；正文变化后同步回检摘要

### A4. 关键词低质量
- 现象: 关键词只有 "数学建模"、"优化"、"分析" 等空泛词
- 修复: 从题目对象、核心方法与关键任务中选择能帮助检索和区分论文的词，避免为了数量堆同义词

### A5. 摘要过短或过长
- 现象: 过短以至缺少方法或结果，或过长到挤压正文并重复背景
- 修复: 先核对当届格式要求，再以覆盖题目任务、方法、可核验结果和适用边界为准调整长度；样本分位只作异常提醒

### A6. 摘要未按"背景+每问一段"骨架组织
- 现象: 背景、方法、结果混在同一大段中，或每问不分段，第一页明显留白
- 修复: 采用"背景 1 段(3—4行) + 每问 1 段(段首'针对问题 X：', 6—8行) + 关键词 1 行"的骨架，逐问独立成段；总段数控制为单倍行距下刚好填满 A4 第一页

## B. 假设与符号类

### B1. 假设无支撑
- 现象: "假设车辆匀速行驶。" (孤立)
- 修复: "假设车辆匀速行驶。依据: 附件 2 数据显示 95% 行程速度方差 < 5 km/h,文献 [3] 在类似场景采用相同假设。"

### B2. 假设清单膨胀
- 现象: 大量相近或不参与后续推导的假设混在一起
- 修复: 合并同义项，删除没有进入公式、算法或验证的假设，并逐条标明依据与影响范围

### B3. 关键假设缺失
- 现象: 直接进入建模，数据机制、边界条件或行为前提没有说明
- 修复: 从实际进入模型的前提出发补齐假设，并说明其依据、适用范围和失效后果，不以条数为目标

### B4. 符号重复定义
- 现象: λ 在 Q1 是衰减系数,在 Q2 是拉格朗日乘子
- 修复: 全文符号表统一,不同含义用下标 (λ_decay, λ_LM)

### B5. 符号无单位
- 现象: 决策变量 x 没有标 "单位: 件" 或 "无量纲"
- 修复: 对有量纲变量标明单位，对无量纲量明确注明，并在数据、公式和结果中保持一致

### B6. 符号在正文出现前未定义
- 现象: 突然冒出一个 ξ
- 修复: 首次出现处给定义或脚注

## C. 模型选型类

### C1. 模型名称与实际实现脱节
- 现象: "我们采用 AHP 模型"
- 修复: 先说明 AHP 在本题承担的作用、输入与局限；只有实际加入动态权重或熵权等机制时，才在名称中如实写出该变体

### C2. 模型与问题不匹配
- 现象: 题目要分类却用了回归; 题目要时序却用了截面回归
- 修复: 用题目的输出形式、数据结构、约束和评价指标检查候选模型；`model_catalog.md` 只用于生成候选，不代替适配性论证

### C3. 候选模型同族
- 现象: 候选 1: BP, 候选 2: RBF, 候选 3: LSTM (都是神经网络)
- 修复: 当存在真实方法权衡时，比较结构、假设或求解机制不同的候选；若同族模型更适合，也应解释差异和筛选依据

### C4. 选型理由薄弱
- 现象: "BP 神经网络应用广泛,故选用"
- 修复: 至少交代与目标、数据、约束、计算预算及验证方案的关系，并引用实际使用的证据

### C5. 不验证求解可行性
- 现象: 选了一个 NP-hard,结果跑不出来
- 修复: 在完整实现前做与主要风险匹配的最小可运行验证，记录问题规模、求解器状态、耗时和失败条件；代码行数不作为标准

### C6. 无意义堆砌复杂高级算法
- 现象: 简单模型已能达标，仍堆砌神经网络/多模型组合/仿真，且说不出选用复杂模型的必要理由
- 修复: 按模型选择规则——简单模型达标则用简单模型；确属高复杂度场景（多目标优化、非线性预测、多维时序等）才用更复杂模型并写明简单模型为何不适用；输出时至少对比简单方案与最终方案的优缺点

## D. 求解类

### D1. 代码缺少可追溯说明
- 现象: 代码没有说明输入、输出、关键步骤及其对应正文位置
- 修复: 在关键步骤写清意图、参数和正文对应关系；注释语言以团队可维护和提交规范为准

### D2. 没做 sanity check
- 现象: 求解器返回结果就直接用,不验算
- 修复: 根据模型风险设计边界、守恒、量纲或已知解检查，并保存输入与预期结果

### D3. 结果数量级离谱
- 现象: 优化得到 -10^9 但题目问的是百分比
- 修复: 求解后立即量纲检查 + 数量级检查

### D4. 用了不可复现的随机种子
- 现象: 结果每次跑都不一样,无 random seed
- 修复: 对随机流程固定并记录种子、软件版本和采样设置；需要多种子评估时报告分布，而不是只固定为某个数字

### D5. 求解时间超出比赛预算且没策略
- 现象: 单次求解占用过多剩余时间，却没有缩放、近似或中止方案
- 修复: stage 3 选型时纳入时间预算; 超时先降问题规模再求

---

### D6. 全链路贪心无全局/精确参照 (优化题高严重度)
- 现象: 求解主线是"就近分配 → 末端 CW → 干线 CVRP → LPT 调度"式的分解流水线，每一步都是局部贪心；结论只有可行解，没有最优性或与最优距离的任何证据
- 风险: 既不能保证离最优多近，也无法回答"为什么这个方案好"，是优化题求解环节最硬的短板；评价章若只写"启发式可行"而不补参照，等于承认弱项却没补缺口
- 修复: 至少补其一——(a) 一层全局优化（遗传算法、ALNS 等元启发式）与贪心解作同指标对比；(b) 一个可算下界（MST 权重、负载往返、LP 松弛）或小规模精确解，报告 `(启发解 − 下界)/下界` 的 gap。两者都无条件完成时，在评价章如实降级为"启发式可行解、未证最优"，禁用"接近最优"等无证据措辞。参照 `templates/shared/solution_quality.md`。

## E. 结果分析类

### E1. 只报数字不解读
- 现象: "得到结果 X = 12.3"
- 修复: "得到结果 X = 12.3,意味着每天最多调度 12 辆车,与现实运营公司平均水平 (10-15 辆) 一致。"

### E2. 不可视化
- 现象: 结果纯表格,无图
- 修复: 选择能回答当前结论的图或表；流程清楚时不必重复画流程图，结果适合精确比较时也可优先用表

### E3. 图表设计妨碍阅读
- 现象: 配色含义不明、字号过小、图型与数据关系不匹配
- 修复: 根据打印尺寸和比较任务选择图型、配色与字号，并检查灰度、色盲和缩放后的可读性；工具本身不是评价标准

### E4. 不与基线对比
- 现象: 只报自己的结果,没说比 baseline 强多少
- 修复: 在存在可比方案时定义基线，并保持相同数据切分、预算和指标；若没有合理基线，应说明原因并采用其他验证证据

## F. 灵敏度类

### F1. 缺少针对关键不确定性的验证
- 现象: 结论依赖估计参数或数据扰动，却没有检查结果是否稳定
- 修复: 按风险选择灵敏度、稳健性、交叉验证、残差诊断或情景分析；是否单列章节取决于题型和当届要求

### F2. 仅 OAT (one-at-a-time)
- 现象: 只单独变 1 个参数
- 修复: 若参数可能交互，增加联合扰动、LHS、Sobol 或情景组合；若单因素分析已足够，应说明独立性依据

### F3. 扰动幅度不切实际
- 现象: 把价格从 100 元扰动到 100 万元
- 修复: 用数据波动、测量误差、业务边界或文献给出扰动范围，并解释为何覆盖了主要不确定性

### F4. 不报告稳健区间
- 现象: "灵敏度分析显示模型稳健"
- 修复: "在 α ∈ [0.3, 0.5], β ∈ [0.2, 0.4] 范围内,目标函数变化 < 5%"

## G. 子问题协调类

### G1. 子问题各做各
- 现象: Q1/Q2/Q3 完全独立,变量符号都不一样
- 修复: 统一同义变量；仅在下游确实依赖上游时显式传递结果，并记录单位、版本和误差

### G2. 子问题模型族冲突
- 现象: Q1 用确定性优化,Q3 突然用蒙特卡罗 (没说为什么)
- 修复: stage 3 选型时统一全文模型族; 切换需在 stage 5 显式说明触发条件

---

### G3. 跨问题配置/指标口径漂移
- 现象: 问题三配置 21 无人机/28 轻车，问题四却成 21/22 且正文无解释；或上下游的参数、收益口径悄悄改变，前后对不上
- 风险: 论文内部不自洽，评委按题号一对照即可发现，属于硬伤
- 修复: 凡下游复用上游配置或结果，显式声明"沿用同一决策规则"还是"锁定数值"；数值变化必须给出差异量与原因（如"双中心使末端配车需求下降"）；每问结果表的指标必须能回指到目标函数的一个符号，口径全文字一致

## H. 模型评价类

### H1. 套话式自我批判
- 现象: "本模型有一定的简化,未考虑某些因素。"
- 修复: 说明具体限制、触发场景、对结论的影响和可行改进；只有在有实验或文献支撑时才估算改进幅度

### H2. 优点夸大
- 现象: "本模型适用于所有情况" / "结果非常准确"
- 修复: 优点也要数据支持,e.g., "在测试集上误差 < 2%,优于基线 5%"

### H3. 推广空泛
- 现象: "可推广至各类相关问题"
- 修复: 给出确有共同机制的场景，并说明需要替换的数据、假设、约束及重新验证步骤；没有合适推广时可如实不写

## I. 写作呈现类

### I1. 公式不编号 / 编号错乱
- 现象: 重要公式无编号,后续无法引用
- 修复: 章节级编号 (5.1)、(5.2) ...; 全文引用格式统一

### I2. 图表无题注或编号错误
- 现象: 图 5、图 6、图 8 (跳过 7)
- 修复: 用 LaTeX 自动编号; Word 用题注

### I3. 引用不规范
- 现象: 只写 "[1]"，参考文献节不存在，或引用样式前后不一致
- 修复: 按当届科技论文格式统一引用；仓库默认建议 GB/T 7714，但不把它包装成官方硬性要求；只列正文实际使用且已核验的来源，正文与列表一一对应

### I4. 字体字号不统一
- 现象: 三个章节用了三种字体
- 修复: 用仓库原创的 `ctexart` marker 模板统一装配，并在提交前对照当届格式要求复核

### I5. 中英文混排无空格
- 现象: "本文用Python求解"
- 修复: 中英之间空格 "本文用 Python 求解"

### I6. 英文缩写首次出现无全称
- 现象: 首次出现直接写 "SARIMA"、"LP"，读者无法知道全称
- 修复: 首次出现写 "季节自回归积分滑动平均（Seasonal Autoregressive Integrated Moving Average, SARIMA）"，并给出中文全称；后文再使用缩写

### I7. 正文引用位置不当
- 现象: 在摘要、结果、结论或展望中突然出现 [1]，或在正文任意位置堆引用
- 修复: 正文引用只放在问题分析与方法首次介绍处；摘要、结果、结论与展望不出现正文引用，参考文献列表与正文一一对应

### I8. 中文标点后多余空格
- 现象: "， " 或 "。 " 中文标点后跟空格，版面参差、不符合中文排版
- 修复: 中文标点后不留空格；英文单词之间按英文规则保留空格；全文标点后空格保持一致

### I9. 图表宽度不当
- 现象: 单图超出版心（>90%）或过小（<50%），双图并排合计超宽或变形
- 修复: 单张图宽度约为版心 70%，多图并排时各图宽度之和也约为 70%，按比例缩放、不拉伸不变形，字号与线宽全文统一

### I10. 子问题未独立成一级章
- 现象: 所有子问题的建模与求解合并在一章，需翻到章内小节才能定位某一问
- 修复: 采用分立式结构，每个子问题单独设置一级标题（六、问题一模型建立及求解；七、问题二模型建立及求解…），每问内部按 X.1 模型建立 / X.2 求解算法（含流程图）/ X.3 求解结果与分析 三段式组织；数据题在建模章之前设独立一级章"五、数据预处理"

### I11. 求解章节子标题层级缺失（缺前置/缺验证）
- 现象: 单问求解章直接堆模型，缺少"前置依据（探索分析/机理推导/变量定义）"与"验证环节（检验/稳健性/算法对比）"子标题，论证链断裂
- 修复: 按题型套用分题型子标题体系（见 paper_skeleton.md）：数据题 X.1 探索分析→X.2 模型设定→X.3 求解→X.4 检验→X.5 结果解读；机理题 X.1 机理建立→X.2 数值方案→X.3 结果可视化→X.4 精度验证；优化题 X.1 变量定义→X.2 模型构建→X.3 算法设计→X.4 结果分析→X.5 算法对比

### I12. 跨页长表缺"续下页"或续页缺三线
- 现象: 符号说明等长表跨页后，续页没有完整三线表结构（缺顶线/表头下线/底线），或非末页结尾没有底线、右下角没有"续下页"小字，读者难以判断表格是否结束或是否续页
- 风险: 三线表规范被破坏、跨页表格阅读断裂，评委阅卷时难以定位"符号/含义/单位"表头
- 修复: 跨页长表（尤指符号说明表）改用 LaTeX `longtable` 四段式：`\endfirsthead` 放第一页顶线+表头+下线；`\endhead` 放续页重复表头（保证每页三条线）；`\endfoot` 放非末页页脚 = 底线 + `\multicolumn{列数}{r}{\footnotesize 续下页}`；`\endlastfoot` 放末页页脚 = 仅底线。模板见 `templates/shared/notation_table.md` §跨页规范

### I13. 表右缘/行内公式超出右边界（左右不对齐）
- 现象: 符号说明表右缘超出正文右边界，或正文中位于句尾的长行内公式（如 `$A\le B\ge C$`）被挤出版心右边界，页面右侧参差
- 风险: 版心右边界被破坏，评委阅卷时视觉杂乱；逐页右边缘不齐会被视为排版硬伤
- 修复:
  1. 表格对齐正文：列用 `p{…\textwidth}` 且宽度之和 = `\textwidth`，并在表前 `\setlength{\tabcolsep}{0pt}`（表尾恢复 6pt）——否则 longtable 列间默认 `\tabcolsep` 会让表格总宽超出版心
  2. 行内公式防溢出：位于句末的长不等式/等式内联块，在关系符（`\le`/`\ge`/`=`）前加 `\allowbreak`，并重排句子提供充足中文断点，避免整块不可断被推挤
  3. 版心兜底：模板导言区开启 `\setlength{\emergencystretch}{3em}`，允许 TeX 在必要时伸缩行界，消除长词/long token 造成的 overfull `\hbox`
  4. 附录代码/超长列表项：手动把超界代码行按版心折行（不改变代码逻辑），长列表改用普通段落让 TeX 自动断行，避免列表续行从缩进处右延超界

### I14. 摘要/节首第一段丢失首行缩进
- 现象: 整篇论文（尤以摘要页）第一段与后续段不同，左沿顶到左边距无 2em 缩进；或正文每节标题后第一段不缩进
- 成因: ① `center`（trivlist）环境结束时会吞掉下一段开头的缩进 token；② `\section*`/`\section` 标题后的 `\@afterheading` 会取消紧接第一段的缩进
- 风险: 首段与其余段参差，被评委视为段落格式不一致的硬伤
- 修复: 在摘要正文 token（`% MATHMODEL:SECTION abstract`）前显式加一行 `\indent` 强制该段缩进 2 字（mathmodel 模板已加）；正文各节若需统一缩进，勿依赖标题后的自动行为
- 校验: 用 PDF 渲染坐标比对首行 x0 与续行 x0（2em≈23.9pt@12pt）；PyMuPDF 会把长段拆成多 block，勿以"每 block 首行 x0 靠左"误判为无缩进

---

### I15. 表内指标无公式定义
- 现象: 结果表冒出"运输成本 6544.07 元/日"，但净收益公式只有 $R-C_p-C_{\rm inv}-C_{\rm ch}$，找不到对应符号
- 风险: 读者无法核对表格数字怎么来的，指标可信度下降
- 修复: 表里每个指标必须回指目标函数的一个符号（如"运输成本 = $C_{\rm inv}+C_{\rm ch}$"），否则补定义或删除该指标

### I16. 约束只有文字无数学式
- 现象: 正文写"无人机起飞不得早于包裹到货"，但没有 $t_r^{\rm dep}\ge \max t_p^{\rm arr}$ 这样的表达式
- 风险: 模型的约束集不完整，读者无法判断目标函数与约束是否闭合，建模严谨性打折
- 修复: 出现"同时 / 不得早于 / 依赖…时刻"等时序措辞时，必须紧跟一个数学式；每个约束动词对应一个约束方程，时序耦合尤其不能只停留在文字

## J. 流程协作类 (Stage 0/1 失败信号)

### J1. 三人都全栈但都不深
- 现象: 三人都"会一点 Python、会一点写作"
- 修复: 根据队员能力和当前阶段明确负责人、复核人及交接产物；角色可以随任务变化

### J2. 选题摇摆
- 现象: 第一天选 A,第二天换 C
- 修复: 在 `decision_log` 记录选择依据、放弃方案与改题触发条件；新证据达到触发条件时及时重评，不设脱离赛程的固定禁改时长

### J3. 写作留到最后一天
- 现象: 临近截止才开始整理正文，结果、图表、引用和合规材料来不及互相核对
- 修复: 根据截止时间预留写作、校对、合规检查和上传缓冲；已稳定的定义、方法与图表可提前写入
